# OPM/OPZ ハードウェアLFO対応 技術検討

**対象読者**: FITOM_X本体の開発者・AI  
**状態**: 設計検討のみで、実装は未着手。現状の配線と、実装に着手する際の設計方針をまとめる。検討の前提としたコードは2026年8月時点のもの。着手する前に「現状の配線」節がコードと合っているかを確かめること

---

## 1. 現状の配線

感度側は配線済みで、`CInstCh::noteOn()`が`enablePM`/`enableAM`を無条件にtrueで呼び、`COPM`がパッチの`hw.AMS`/`hw.PMS`をreg`$38+ch`へ書く。発生器側はCC#14/#15(`hwLfoDepth_`/`hwLfoRate_`→`setLFODepth`/`setLFORate`)経由のみで、初期値0のためCCを送らない限り無音変調になる。LFO波形(reg`$1B`)はパッチにもCCにも無く、`$1B`への書き込み自体が存在しないため常に波形0固定。OPZの第2LFOは`COPZ`が`COPM`を継承するだけで未実装(旧FITOMも未実装)

## 2. パッチ側フィールド

`FmHwVoice`が持つHW LFO関連は`AMS`(2bit)/`PMS`(3bit)と、オペレータ単位の`FmHwOp::AM`(1bit)のみ。`LFRQ`/`PMD`/`AMD`/波形に相当するフィールドは**意図的に持たない**(チップ内蔵LFOがチップ全体で1系統の共有リソースであり、マルチティンバー・ダイナミックボイスアサインと相性が悪いため)

## 3. OPZレジスタ仕様

出典: <http://sr4.sakura.ne.jp/fmsound/opz.html>、TX81ZのシステムROM解析

`$16`=LFRQ2 / `$17`=AMD2(b7=0)・PMD2(b7=1) / `$18`=LFRQ / `$19`=AMD・PMD(同b7) / `$1B`=CT(b7-6)・SY2(b5)・SY(b4)・LW2(b3-2)・LW(b1-0)。`$38+ch`は**b7がPMS/PMS2のセレクタ、b2がAMS/AMS2のセレクタ**で、値はb6-4(PMS側)とb1-0(AMS側)。1回の書き込みでPM側とAM側の窓を独立に選べる

## 4. 設計方針(結論)

パッチにAMS2/PMS2を追加する必要は無い。実機TX81Zも**LFO選択はボイスデータではなくパフォーマンスデータ側のチャンネル単位パラメータ**(`{off/LFO1/LFO2/Vibrato}`、うちVibratoはソフトウェアによるピッチモジュレーション=FITOM_Xの`sw.LFR>0`ソフトLFOに相当)であるため、FITOM_Xも**明示選択のパフォーマンスパラメータ**として持たせる。これによりLRU/スチール等の自動割り当て器は不要になり、動作が決定的になる。リソース競合は「同じインスタンスを選んだMIDIチャンネル間では後発優先」で解決し、`lfoCount_==1`のOPM/OPPでは現行動作にそのまま縮退するためチップファミリー間の一貫性も保てる

## 5. 着手前に修正が必要な既存の不具合

(1) `COPM::enablePM`/`enableAM`が`$38+ch`をread-modify-writeしている(`(getReg(...) & 0x07) | ...`)。保持マスク`0x07`にAMS側セレクタb2が含まれるうえ、`getReg()`が返すシャドウ1バイトでは窓ごとに別値を持つ`$38+ch`を表現できないため、OPZでは必ず破綻する。ドライバ側に8ch分の`{PMS, AMS, PMS2, AMS2}`を持ちフルバイトを組み立てて書く方式に変える(`$40`/`$C0`の窓切り替えは`COPZ::updateVoice`が既にこの方式で正しい)。窓の切り替え時は旧窓へ0を書くクリアが別途必要で、怠るとそのチャンネルが両方のLFOを受ける。(2) `COPM::reset()`のレジスタクリアが`$20`〜`$FE`でLFOレジスタ`$18`/`$19`を含まない一方、`lfoDepth_`/`lfoRate_`キャッシュは0に戻るため、`setLFODepth`/`setLFORate`の同値早期リターンと組み合わさって実チップに古い値が残る。`init()`での`$1B`初期化も同様に必要(`getReg($1B)`のRMWがCT(b7-6)を壊さないようにするため)

## 6. CC割り当て案

CC#14/#15(Depth/Rate、既存)は「そのMIDIチャンネルが選択中のインスタンス」へ書く解釈に変更し、CC#20=LFO波形(0-3)、CC#21=LFO SELECT(0=off/1=LFO1/2=LFO2)、CC#22=キーオン同期(`$1B`のSY/SY2、任意)を新設する。CC#16-19はGM1で"General Purpose Controller"の名前が付くため避け、完全な未定義域を使う

## 7. 未確認事項

FitomEmuIF(YMEngine)側がOPZの第2LFO(`$16`/`$17`)、`$1B`のLW2/SY2、および`$38+ch`のセレクタビットb7/b2をエミュレートしているか。特にセレクタビット未実装の場合、AMS2/PMS2への書き込みがAMS/PMSを上書きする形で誤動作する。あわせて`COPZ::init()`が資料のシステム初期化のうち`$1C`/`$1E`への`$00`書き込みを行っていない(資料でもLFO関係と推測されている番地)

## 8. 実装順

①`$38`のRMW廃止 + `reset()`/`init()`のLFOレジスタ初期化(現行動作を壊さない土台固め) → ②LFO1の波形/SELECT CC追加 → ③OPZ第2LFO
