# FITOM_X バンクファイル リファレンス

音色バンク・ドラムキット・PCMバンクのファイルを書く人のためのリファレンスです。各ファイルをどう書き、プロファイルからどう読み込ませるかをまとめます。

関連するリファレンス:
- 音色(HwPatch)の各パラメータ: [HwPatch リファレンス](./hwpatch-reference.md)
- 演奏特性(SwPatch)の各パラメータ: [SwPatch リファレンス](./swpatch-reference.md)
- レイヤードパッチ(`*.patchbank.json`): [レイヤードパッチ リファレンス](./layered-patch-reference.md)
- プロファイルの書き方全体: [プロファイル リファレンス](./profile-reference.md)
- MIDIでのバンク・プログラムの選び方: [MIDIメッセージリファレンスマニュアル](./midi-message-reference.md)の「2.2 バンクセレクト / プログラムチェンジ」

## 1. バンクファイルの種類と読み込み

バンクファイルは、プロファイルの`banks`に並べて読み込ませます。

| ファイル | 中身 | プロファイルでの登録先 | 登録のキー |
|---|---|---|---|
| `*.hwbank.json` | 音色(HwPatch)最大128個 | `banks.hw_banks[]` | `group`(チップ種別)+`bank` |
| `*.samplezonebank.json` | AWM(OPL4のPCM部)の音色 | `banks.hw_banks[]` | `group`(`"AWM"`)+`bank` |
| `*.swbank.json` | 演奏特性(SwPatch)最大128個 | `banks.sw_banks[]` | `bank` |
| `*.patchbank.json` | レイヤードパッチ最大128個 | `banks.patch_banks[]` | `bank` |
| `*.drumkit.json` | ドラムキット1つ | `banks.drum_banks[]` | `prog` |
| `*.pcmbank.json` | ADPCM系チップの波形データの目録 | `banks.pcm_banks[]` | `bank`(+`group`/`chip`) |
| SCC波形バンク | SCCの波形メモリの内容 | `banks.scc_wave_banks[]` | `bank` |
| SoundFont(`*.sf2`) | SF2直行パスで使う音源 | `banks.sf2_banks[]` | `bank` |

`file`に相対パスを書いた場合は、**そのプロファイルファイルが置かれたディレクトリ**を起点に解決されます(FITOM_Xを起動したときのカレントディレクトリは関係しません)。プロファイルとバンク一式をどこに置いても、同じ結果になります。

例えば`config/profiles/preset_opn.profile.json`から、リポジトリ直下の`banks/`を参照するには`"../../banks/OPN/gm/necopn_gm.hwbank.json"`のように書きます。プロファイルと同じディレクトリに`banks/`を置く場合は`"banks/OPN/gm/xxx.hwbank.json"`と書けば足ります。

`*.pcmbank.json`の中に書く`adpcm_json`/`bin_file`の相対パスは、その`*.pcmbank.json`自身が置かれたディレクトリを起点に解決されます。

`banks`の中身を別のファイルに分けて複数のプロファイルで共有する方法と、共有した内容の一部だけをプロファイルごとに差し替える方法(`bank_overrides`)は、[プロファイル リファレンス](./profile-reference.md)を参照してください。

## 2. 音色バンク(`*.hwbank.json`)

### チップ種別とバンク番号

1つの音色バンクには、1種類のチップ向けの音色だけを入れます。どのチップ向けのバンクかは、ファイルの中ではなく、プロファイルの`hw_banks[]`の`group`で決まります。

```json
{ "group": "OPZ", "bank": 0, "file": "banks/OPZ/tx81z/tx81z_1.hwbank.json" }
```

この例では、ファイルの音色がOPZ用のバンク0として登録され、MIDIではCC#0=OPZ・CC#32=0で選べます。

- バンク番号はチップ種別ごとに独立しています。OPM用のバンク0とOPZ用のバンク0は別のものです
- `group`だけを変えて同じファイルを複数回登録すれば、同じ音色を複数のチップ種別から選べます(例: 同じOPM用のファイルを`"OPM"`と`"OPZ"`の両方に登録すると、CC#0がOPMでもOPZでも選べます)
- 音色の`ops[]`の要素数は、チップのオペレータ数に合わせます([HwPatch リファレンス](./hwpatch-reference.md)の「1. 共通フィールド構成」)

### 同じファミリーでは最上位のチップで登録する

同じチップファミリーの中では、**最も機能の多いチップ**の種別でバンクを登録することを勧めます。

| ファミリー | 登録に使う`group` |
|---|---|
| OPN系 | `OPN2` |
| OPL系 | `OPL3_2` |
| OPM系 | `OPZ2` |
| PSG系 | `SSG`(次の「PSG系の共有バンク」) |

音色を鳴らすとき、要求されたチップが無くても、同じファミリーの下位のチップで表せる内容(下位のチップに無い機能を使っていない音色)なら、FITOM_Xは自動的に下位のチップで鳴らします。上位のチップで登録しておけば、下位のチップしか無い環境でも鳴り、上位用と下位用のバンクを別々に用意する必要がありません。上位のチップにしか無い機能(OPL3の正弦波以外の波形等)を使った音色は、下位のチップしか無い環境では鳴りません。

OPLL系(OPLL/OPLLP/OPLLX/VRC7/OPLLEX)は、ユーザー音色ならファミリーの中で互いに代わりに鳴らせます。内蔵ROMのプリセット音色はチップごとに中身が違うので、代わりに鳴らすことはしません(OPLLEXだけは例外。下記)。

### PSG系の共有バンク

SSG(YM2149/AY-3-8910)・EPSG(AY8930)・DCSG(SN76489)・SAA(SAA1099)・SCC(K051649/K052539)は、すべて1つのバンク空間を共有します。チップごとの機能の差は大きい一方で、1チップあたりの音色の種類が少なく、チップごとにバンクを分けると番号が埋まらないためです。

- PSG系の音色バンクは`group: "SSG"`で登録してください。MIDIのCC#0にEPSG/DCSG/SAA/SCCのどれを送っても、バンクは`SSG`の空間から探されます。`group`に`"EPSG"`/`"DCSG"`/`"SAA"`/`"SCC"`を指定して登録したバンクは、この検索で見つかりません
- 実際にどのチップで鳴らすかは、音色ごとに`ext.target_voice_patch_type`で指定します(SSG/EPSG/DCSG/SAA/SCCのいずれかのチップ種別の値)。同じバンクの中にSSG用の音色とSCC用の音色が混ざっていて構いません
- `ext.target_voice_patch_type`を省略した(0の)音色は、プロファイルの`psg_fallback_chip`で指定したチップ(省略時はSSG)で鳴ります
- PSG系の音色は、指定したチップが無いときに別のPSG系チップで代わりに鳴らすことはしません

### OPLL系のROMプリセット音色(バンク0)

OPLL系チップ(OPLL/OPLLP/OPLLX/VRC7/OPLLEX)のバンク0は、チップに内蔵されたROMのプリセット音色のための領域です。ファイルを用意する必要は無く、バンク0にファイルを登録しても使われません。Program Changeの値で、次のように音色を選びます。

| ビット | 内容 |
|---|---|
| 上位3bit(prog÷16) | どのチップのROMか。0=OPLL(YM2420を含む)/1=OPLLX/2=OPLLP/3=VRC7(4-7は無音) |
| 下位4bit(prog÷16の余り) | ROM音色の番号。0=無音(ユーザー音色と区別するため)、1-15=ROM音色 |

例えばprog=0x23は、OPLLPのROM音色3番です。

- 指定したチップが接続されていない場合、OPLLEXが接続されていればOPLLEXで鳴ります(OPLLEXは4種類のROMをすべて持っています)。それ以外のチップの代わりには鳴りません
- CC#0でOPLLEXを選んだときも、同じ番号の付け方でバンク0が使えます。この場合、上位3bitはOPLLEX自身のどのROMバンクを鳴らすかを意味します

### ROM音色・ビルトイン音色に演奏特性を付ける

OPLL系のROM音色と、DSG(YM2163)のビルトイン音色は、音色データとしてのファイルを持たないため、そのままでは演奏特性(パフォーマンスパッチ)を指定できません。演奏特性を付けるには、専用のメタバンクを1つ作ります。

1. プロファイルの`hw_banks[]`に、`"role": "builtin_swpatch_meta"`を付けたエントリを足します。`group`/`bank`はこの場合意味を持ちませんが、省略はできません。

   ```json
   { "group": "OPLL", "bank": 0, "file": "banks/OPLL/rom_sw_meta.hwbank.json",
     "role": "builtin_swpatch_meta" }
   ```

2. このファイルの各エントリには、`ops`の代わりに`builtin`で対象の音色を書き、`sw_bank`/`sw_prog`で演奏特性を指定します(`ops`と`builtin`はどちらか一方だけを書きます)。

   ```json
   { "prog": 0, "builtin": { "patch_type": "OPLL", "patch_no": 3 },
     "sw_bank": 2, "sw_prog": 5 }
   ```

   この例は、OPLLのROM音色3番に、演奏特性バンク2のプログラム5を付けます。

| `patch_type` | `patch_no` | 対象 |
|---|---|---|
| `OPLL` / `OPLLX` / `OPLLP` / `VRC7` | 1〜15 | OPLL系のROM音色。0は無音として予約 |
| `DSG` | 0〜19 | DSGのビルトイン音色。**0も正規の音色**です([HwPatch リファレンス](./hwpatch-reference.md)の「10.1 DSG」) |

- OPLL系とDSGのエントリは1つのファイルに混ぜて書けます。メタバンクは1つしか持てず、`"role": "builtin_swpatch_meta"`を複数指定すると後に書いたものだけが使われるので、必ず1ファイルにまとめてください
- **`prog`は音色の識別子ではなく、ファイル内の格納位置**です。対象は`patch_type`と`patch_no`だけで探されます。同じ`prog`を2回使うと後のものが前のものを上書きして消すので、`prog`は省略する(自動で採番されます)か、チップごとに範囲を分けてください(例: OPLL系 0〜59、DSG 60〜79)。重複や`builtin`の書き忘れはログに警告が出ます
- 通常の音色エントリ(`ops`を持つもの)では、`prog`は省略できません
- 対応するエントリが無い音色は、演奏特性が付かないだけで、通常どおり鳴ります

## 3. ドラムキット(`*.drumkit.json`)

リズムチャンネルは、ドラムバンク(番号0固定)の中から、Program Changeでドラムキットを選びます。プロファイルの`drum_banks[]`には、**Program Changeの番号ごとに1つのファイル**を割り当てます。

```json
"drum_banks": [
  { "prog": 0, "name": "OPL4 AWM GM std kit", "file": "opl4awm.drumkit.json" },
  { "prog": 1, "name": "OPNA/B GM std kit",    "file": "opnAdpcm.drumkit.json" }
]
```

ドラムキットのファイルは`"type"`で2つの書き方を選べます。

### `"routed"`: ノートごとに音色を割り当てる

`notes[]`に、MIDIノート番号ごとの割り当てを並べます。FM音源のように、ドラム音の1つ1つが別の音色として定義されている場合に使います。

| フィールド | 内容 |
|---|---|
| `note` | このエントリが受け持つMIDIノート番号 |
| `name` | 名前(表示用) |
| `voice_patch_type` | 音色の選び方。MIDIのCC#0と同じ意味です(下表) |
| `patch_bank` / `patch_prog` | 音色のバンクとプログラム。意味は`voice_patch_type`で変わります(下表) |
| `play_note` | 実際に鳴らすノート番号 |
| `fine_tune` | 音程の微調整(1半音=64段) |
| `pan` | 定位 |
| `gate_time` | 発音を続ける時間 |
| `sw_bank` / `sw_prog` | このノートの演奏特性。指定すると、音色自身が持つ演奏特性より優先されます。指定先が見つからなければ、音色自身の演奏特性が使われます |

| `voice_patch_type` | `patch_bank` | `patch_prog` |
|---|---|---|
| 0(省略時) | レイヤードパッチのバンク | レイヤードパッチのプログラム |
| `0x01`-`0x6F`(チップ種別) | そのチップの音色バンク | 音色バンク内のプログラム |
| `0x70`(内蔵リズム) | 対象のチップ(0x11=OPNA、0x28=OPLL、0x44=DSG) | 内蔵リズムの楽器(チャンネル)番号 |
| `0x7F`(無音) | 使わない | 使わない |

チップ種別を直接指定できるので、例えばキックはOPN、スネアはOPL、ハイハットはPSG、のように1音ずつチップを変えたキットを、レイヤードパッチを用意せずに作れます。内蔵リズムの楽器番号が範囲外のときは、そのノートは鳴りません(別の楽器が鳴るよりは鳴らないほうが安全なため)。OPLLの内蔵リズムが無い構成では、OPLLEXの内蔵リズムで鳴ります。

### `"direct"`: 1つの音色にまとめて渡す

`[note_min, note_max]`の範囲のノートを、すべて1つの音色(`patch_bank`/`patch_prog`)へそのまま渡します。OPL4のAWMのように、音色自身がノートごとの波形の切り替えを持っている場合に使います。ノートの数だけ同じ記述を並べずに済みます。

```json
{
  "type": "direct",
  "name": "OPL4 AWM GM std kit",
  "patch_bank": 10,
  "patch_prog": 0,
  "note_min": 27,
  "note_max": 87
}
```

この例の`patch_bank: 10`は、AWM用の音色を指すレイヤーを持つレイヤードパッチのバンクです。

### チョークグループ

ハイハットのクローズとオープンのように、片方が鳴るともう片方をすぐに止めたい音は、`"routed"`のキットのトップレベルに`choke_groups`として、同時に鳴らさないノート番号の組を並べます。

```json
{
  "type": "routed", "name": "Standard Kit",
  "choke_groups": [[42, 44, 46]],
  "notes": [ ... ]
}
```

- 同じ組のノートが鳴ると、組の他のノートはチップに関係なく強制的に消音されます。各ノートが別々のチップ・別々の音色を使っていても働きます
- 同じノートを続けて鳴らしたときは、前の音を止めてから鳴らします(組に入れる必要はありません)
- 消音できるのは、ノートオフ(または`gate_time`の経過)からおよそ2秒以内の音です。それを過ぎても鳴り続ける長いサンプルは、チョークで止まりません

## 4. PCMバンク(`*.pcmbank.json`)

ADPCM-B・ADPCM-A・PCM-D8・SSGS-ADPCMの波形データの目録です。どの波形がメモリのどこにあるか(`entries[]`)と、波形データのファイル(`bin_file`)を持ちます。

プロファイルの`pcm_banks[]`のエントリには、次のキーを書けます。

| キー | 内容 |
|---|---|
| `bank` | バンク番号 |
| `file` | `*.pcmbank.json`のパス |
| `group` | `"ADPCMB"` / `"ADPCMA"` / `"PCMD8"` / `"SSGS_ADPCM"`。指定すると、そのチップの音色として、波形1つにつき1つの音色を自動で作ります(下記)。省略すると、波形データの登録だけを行います |
| `chip` | 波形データの配置が違うチップごとにバンクを分けるときに、対象のチップを指定します(`"OPNA"` / `"OPNB"` / `"OPNBB"` / `"Y8950"`)。同じADPCM-Bでも、OPNAとOPNB/OPNBBでは波形データの区切りの単位(32バイト / 256バイト)が違い、同じ目録を共有できないためです |
| `offsets_only` | `true`にすると、波形の配置の目録としてだけ登録し、音色の自動作成をしません。`chip`違いのバンクを同じ`group`で複数登録すると、同じ名前の音色がパッチピッカーに重複して並ぶので、代表の1つ以外にこれを指定します |

```json
{ "group": "ADPCMA", "bank": 1, "file": "banks/PCM/pss680/pss680_opnb.pcmbank.json" }
```

**音色の自動作成**: `group`を指定すると、`entries[]`の各波形から、`prog`=波形の番号・名前=波形の名前・ゾーン1つ(全ノート・全ベロシティ、`wave_index`=波形の番号、`root_note`=波形の`root_note`[省略時69])の音色を自動で作ります。`*.samplezonebank.json`を手で書かなくても、パッチピッカーで個々の波形を選んで鳴らせます。音色のバンク番号は`pcm_banks[]`の`bank`で、チップ種別ごとに独立しています(AWMのバンク0とADPCM-Bのバンク0は別のものです)。

**演奏特性を付ける**: `*.pcmbank.json`のトップレベルの`swpatches[]`に`{ "entry_no": 波形の番号, "sw_bank": …, "sw_prog": … }`を並べると、自動で作る音色にその演奏特性が付きます。

SSGS-ADPCM(YMZ705/YMZ732)は、波形の開始/終了アドレスをチップ自身がメモリ先頭の表から読むため、`entries[]`のアドレスは音に関係しません(波形の有無と名前にだけ使われます)。音程は変えられず、`sample_rate`(4000/8000/16000/32000のいずれか)がそのままチップの再生レートになります。

AWMの音色(`*.samplezonebank.json`)の書き方は、[HwPatch リファレンス](./hwpatch-reference.md)の「14. ADPCM-B / ADPCM-A / PCM-D8 / AWM」を参照してください。
